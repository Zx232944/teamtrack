# 队迹协作工具 4 个新需求实施方案

## Context

用户在使用过程中提出 4 个改进需求：
1. 注册流程繁琐（手机号授权步骤多余），需要简化为仅昵称
2. 队伍时间线进度无法手动控制，自动按任务完成率计算不符合实际竞赛节奏
3. 任务发布仅支持文字描述，无法附件化说明（如需求文档、设计稿、参考链接）
4. 多处列表未显示操作人（首页动态字段名 BUG、任务卡缺创建者、交付物记录缺上传人），协作场景下无法追溯"谁做的"

本方案在尽量复用现有工具/模式的前提下完成 4 个需求，保持暗色主题与代码风格一致。

## 需求 2：队伍时间线队长手动设置

### 数据结构

- teams 表新增字段 `currentStep: number`（默认 1，含义"当前进行到第几步"）
- timeline 计算：`step < currentStep` 为 done，`step === currentStep` 为 current

### updateTeam 云函数核心逻辑

```js
const { teamId, currentStep } = event
const teamRes = await db.collection('teams').doc(teamId).get()
if (!teamRes.data) return { code: -1, message: '队伍不存在' }
if (teamRes.data.captainId !== openid) return { code: -1, message: '只有队长可以修改进度' }
const step = Number(currentStep)
if (!Number.isInteger(step) || step < 1 || step > 6) return { code: -1, message: '步骤值无效' }
await db.collection('teams').doc(teamId).update({ data: { currentStep: step } })
return { code: 0, data: { currentStep: step } }
```

### onTimelineTap 交互

- 非队长：toast "只有队长可以修改进度"
- 队长点击：弹确认框"确定将当前进度设置为「XX」吗？"（回退时文案带"回退"）
- 允许回退（5 → 3）

### 部署

- **新建部署**：`updateTeam` 云函数
- **重新部署**：`createTeam` 云函数

### 兼容性

- 历史队伍无 `currentStep`：`team.currentStep || 1` 默认第 1 步为 current
- `team.progress`（任务完成率）保留，仍用于"完成度"显示

### 上传策略

- **选择时立即上传**到云存储 `taskAttachments/{timestamp}_{fileName}`，拿到 fileID 后加入 attachments 数组
- 提交表单时只传 fileID 数组（与 taskDetail.js 现有逻辑一致）
- 取消创建会留下孤儿文件（可接受，与 deliverables 一致）

### 预览复用

- 提取 `previewFile(deliverable)` 方法，`onPreviewDeliverable` 和 `onPreviewAttachment` 都调用它
- 图片用 `wx.previewImage`，其他用 `wx.openDocument`，链接复制

### 部署

- **重新部署**：`createTask` 云函数（同时新增 attachments 和 createdByName）

### 兼容性

- 历史任务无 `attachments`：`task.attachments || []` 返回空数组，taskDetail 不显示附件 section
- 附件路径 `taskAttachments/` 与交付物 `deliverables/` 分离

## 实施顺序

按风险从低到高：

1. **需求 4**（显示修复）：改动最小、风险最低，先修复 BUG 让现有数据正确显示
2. **需求 1**（注册 UI）：独立模块改动，不影响其他功能
3. **需求 2**（时间线）：涉及新建云函数和 DB 封装
4. **需求 3**（任务附件）：改动最复杂（上传 + 预览复用）

每个需求完成后独立验证。
