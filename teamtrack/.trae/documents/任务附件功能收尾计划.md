### 待完成

#### 1. `cloudfunctions/createTask/index.js`（Task #27）

当前 `db.collection('tasks').add({ data: {...} })` 的 data 对象**没有 attachments 字段**，前端传过来的 `event.attachments` 会被丢弃。需要在 data 中加一行。

附件数据结构（由前端 createTask.js 写入）：
```js
{ type: 'file'|'link'|'image', fileName, fileID, fileUrl, size }
```
- file/image 类型：fileID 有值，fileUrl 为空字符串
- link 类型：fileID 为空字符串，fileUrl 为链接地址，size 为 '链接'

#### 2. `pages/taskDetail/taskDetail.js` + `taskDetail.wxml`（Task #28）

**taskDetail.js 现状**：
- `loadDetail` 中已有 `fileIcons` 映射（docx/pdf/png/jpg 等），目前仅用于处理 deliverables
- `onPreviewDeliverable(e)` 方法已实现完整预览逻辑（链接→复制、图片→wx.previewImage、其他→下载+openDocument/saveToLocal）
- 但该逻辑**与 deliverable 数据结构耦合**（依赖 `deliverable.isLink`、`deliverable.fileID`、`deliverable.fileUrl`、`deliverable.fileName`）

**附件与交付物的字段差异**：
| 字段 | 交付物 (deliverable) | 附件 (attachment) |
|------|---------------------|-------------------|
| 链接标记 | `isLink: true` | `type: 'link'`（无 isLink 字段） |
| 链接地址 | `fileUrl` | `fileUrl`（一致） |
| 文件 ID | `fileID` | `fileID`（一致） |
| 文件名 | `fileName` | `fileName`（一致） |

**核心改造思路**：抽取一个统一的 `previewFile(file)` 方法，接收归一化后的对象 `{ fileName, fileID, fileUrl, isLink }`，让 `onPreviewDeliverable` 和新增的 `onPreviewAttachment` 都调用它。这样避免逻辑重复，也规避字段差异。

**taskDetail.wxml 现状**：有任务描述/截止时间/负责人/交付物 4 个 section，**缺任务附件 section**。需要插入到「任务描述」之后、「截止时间」之前。

### 文件 2：`e:\编程\CY\teamtrack\pages\taskDetail\taskDetail.js`

**改动 B**：抽取 `previewFile(file)` 共享方法。

把 `onPreviewDeliverable` 中从「链接判断」开始的逻辑（约第 218-299 行）抽到独立方法 `previewFile(file)`，参数为归一化对象：
```js
// 归一化：把 deliverable/attachment 统一成 { fileName, fileID, fileUrl, isLink }
previewFile(file) {
  // 1. 链接类型
  if (file.isLink && file.fileUrl) { this.openLink(file.fileUrl); return }
  // 2. 无 fileID 的非链接（兼容旧数据/异常数据）
  if (!file.fileID) {
    if (file.fileUrl) { this.openLink(file.fileUrl); return }
    wx.showToast({ title: '该文件无预览内容', icon: 'none' }); return
  }
  // 3. 图片类型 → wx.previewImage
  // 4. 其他文件 → actionSheet 选择预览/保存
  // （原 onPreviewDeliverable 的完整逻辑搬过来）
}
```

**改动 C**：`onPreviewDeliverable` 改为薄包装，归一化后调 `previewFile`：
```js
onPreviewDeliverable(e) {
  const d = e.currentTarget.dataset.item || {}
  this.previewFile({
    fileName: d.fileName,
    fileID: d.fileID,
    fileUrl: d.fileUrl,
    isLink: !!d.isLink
  })
}
```

**改动 D**：新增 `onPreviewAttachment`，同样归一化后调 `previewFile`：
```js
onPreviewAttachment(e) {
  const a = e.currentTarget.dataset.item || {}
  this.previewFile({
    fileName: a.fileName,
    fileID: a.fileID,
    fileUrl: a.fileUrl,
    isLink: a.type === 'link'   // 附件用 type 字段判断链接
  })
}
```

**为什么**：附件的链接类型用 `type === 'link'` 标识（无 `isLink` 字段），交付物用 `isLink: true`。归一化层消除这个差异，让核心预览逻辑只写一份。

## 假设与决策

1. **附件不做删除/编辑**：任务发布后附件即固定，队员只能查看预览。这符合"任务描述"的语义——附件是任务说明的一部分，不是交付物。
2. **附件预览复用交付物预览逻辑**：链接→复制、图片→wx.previewImage、文件→下载+openDocument/保存。统一走 `previewFile` 方法。
3. **附件 section 仅在有附件时显示**：`wx:if="{{taskAttachments.length > 0}}"`，避免空 section 占位。
4. **不新增 taskDetail.wxss 样式**：复用 `.deliverable-list`/`.deliverable-item`/`.del-icon`/`.del-info`/`.del-name`。
5. **附件的 `size` 字段已是格式化字符串**（前端 createTask.js 的 formatSize 处理过），taskDetail 直接显示，不重复格式化。
