## 1. Demo 简介

### 是什么
**队迹协作工具**是一款基于微信云开发的大学生竞赛队伍协作管理微信小程序。帮助竞赛队伍实现**任务分工、进度跟踪、交付物管理**的全流程协作。

### 面向谁
参加各类学科竞赛的大学生团队——挑战杯、互联网+、数学建模、大创、计算机设计大赛等。核心用户是**竞赛队伍的队长和队员**，尤其是 2-6 人的中小团队。

### 主要功能

| 功能模块 | 详细说明 |
|---------|---------|
| **队伍管理** | 创建队伍、通过队伍ID搜索加入/退出队伍、成员列表查看 |
| **竞赛时间线** | 展示6阶段竞赛生命周期（组队→方案设计→分工→制作→完善→提交），**仅队长可点击设置当前进度**，支持推进和回退 |
| **任务发布（含附件）** | 队长发布任务时可附带三种类型附件：文件上传（任意格式文档）、在线链接（飞书/腾讯文档等）、图片上传，任务包含分值和描述 |
| **任务认领与完成** | 队员主动认领任务，完成后上传交付物（文件或链接），交付记录显示上传人 |
| **队伍动态** | 首页实时展示队伍操作动态流（创建队伍、发布任务、认领任务、上传交付物等），显示操作人和时间 |
| **贡献排行** | 按完成任务分值累加计算贡献值排行榜，点击队员可查看其所有已完成任务和交付物 |
| **个人中心** | 仅需设置昵称即可注册（无需手机号授权），退出登录/退出队伍 |

### 页面结构（11个页面）

- **首页动态**（tab）：队伍操作动态流
- **任务中心**（tab）：查看/认领/完成任务
- **贡献排行**（tab）：成员贡献值排行与交付物
- **个人中心**（tab）：注册/个人信息
- **队伍管理**：队伍信息、成员列表、竞赛时间线
- **队伍列表**：查看已加入的所有队伍
- **发布任务**：创建含附件的任务
- **创建队伍**：输入队伍名称和竞赛名称创建新队伍
- **任务详情**：任务信息与附件预览
- **队友详情**：查看特定队友的贡献和交付物
- **个人统计**：个人任务完成情况统计

## 2. Demo 创作思路

### 灵感来源
身边同学参加竞赛时，队伍协作存在三个普遍痛点：

**痛点一：分工不透明。** 队长把任务发在微信群里，谁认领了、做到哪一步了、做完没有，全靠人工追踪。队员也不知道除了自己之外别人在做什么。

**痛点二：进度不可控。** 竞赛有明确的时间节点（方案设计→制作→提交），但队伍经常到截止日期才发现还没做完，缺乏一个全局的进度把控手段。

**痛点三：交付物散落。** 方案文档在飞书里、代码在 GitHub 上、海报在 Figma 里、截图在微信聊天记录中。等到提交时，队长要从十几个聊天记录里翻找各人提交的材料。

### 为什么做这个方向
1. **微信小程序是大学生最低门槛的载体**——每天打开微信，不需要额外下载 App
2. **微信云开发让后端成本趋近于零**——不需要自己买服务器，云函数按调用量计费，适合小团队使用
3. **市面上缺少专为"竞赛场景"设计的轻量工具**——飞书/企业微信太重，Trello/Notion 需要科学上网，钉钉偏向企业管理。竞赛队伍需要的是一个"打开即用、用完即走"的工具

### 我的取舍
- **不做什么**：不做即时通讯（微信群已经解决了）、不做云端文档编辑（飞书/腾讯文档做得更好）
- **重点做什么**：任务分配 + 进度可视化 + 交付物聚合。这三件事是微信群解决不了的

## 4. TRAE 实践过程

### 整体开发流程

这个项目**完全使用 TRAE IDE** 开发，没有手动写过一行传统代码。从 0 到 1 共经历了 7 个阶段：

### 阶段一：项目初始化与技术选型（约 1 小时）

**目标**：搭建小程序骨架，配置云开发环境

**TRAE 交互**：
- 使用 TRAE 的 `web-dev` 技能生成微信小程序基础项目框架
- 配置 `app.json`（页面路由、tabBar、深色主题）
- 初始化云开发环境 `cloud1-d8g501yg926149990`

**关键 Prompt 示例**：
> "创建一个微信小程序项目，使用云开发模式，包含 4 个 tab 页面：首页（队伍动态）、任务中心、贡献排行、个人中心。使用深色主题 #0F0F1A 背景，#FF6B35 为主色。"

### 阶段二：用户系统与云开发基础层（约 2 小时）

**目标**：实现微信登录 + 昵称注册，封装云 API 调用层

**关键成果**：
- `utils/cloud.js` —— 226 行，封装了云函数调用、数据库查询、文件上传/下载等 10 个方法
- `utils/auth.js` —— 244 行，封装登录注册流程
- `utils/db.js` —— 451 行，数据访问层，封装 27 个业务方法
- 注册云函数 login、register、updateUser

**TRAE 能力运用**：
- 用 TRAE 生成了完整的云函数代码（含鉴权逻辑和数据校验）
- TRAE 帮忙设计了缓存策略（30s 内存缓存 + 60s storage 缓存，避免频繁调用云函数）

### 阶段三：队伍管理系统（约 2 小时）

**目标**：队伍创建、加入/退出、成员管理

**关键成果**：
- 云函数：createTeam、joinTeam、quitTeam、getMyTeams、getTeamData
- 页面：创建队伍页、队伍列表页、队伍管理页
- 缓存策略：`appStore.js` 实现 60s TTL 缓存，`onShow` 时带 `_force=true` 参数强制刷新

**遇到的坑 & TRAE 如何解决**：
- **问题**：跨设备同步不及时，一端创建队伍后另一端不显示
- **TRAE 解决**：分析了代码后建议加时间戳缓存失效机制 + onShow 强制刷新，问题解决

### 阶段四：任务系统与时间线（约 3 小时）

**目标**：任务的完整生命周期（发布→认领→完成），竞赛时间线

**关键成果**：
- 云函数：createTask、claimTask、completeTask、updateTeam
- 页面：发布任务页、任务中心页、任务详情页
- 附件功能：支持文件上传、图片上传、在线链接三种附件类型
- 时间线：队长可点击设置当前进度，支持推进/回退

**TRAE 能力运用**：
- TRAE 自动设计了附件的数据结构：`{ type: 'file'|'link'|'image', fileName, fileID, fileUrl, size }`
- 预览逻辑通过 `previewFile()` 统一处理，支持 fileID 下载和 URL 跳转

### 阶段五：贡献排行与交付物（约 2 小时）

**目标**：贡献值计算、交付物管理、队友详情查看

**关键成果**：
- `computeStats()` 纯函数从任务数据计算贡献值
- 交付物记录显示上传人名
- 点击队员可进入详情页查看其所有已完成任务和交付物

### 阶段六：动态流与首页（约 1 小时）

**目标**：实时活动动态展示

**关键成果**：
- `getActivities()` 获取队伍操作记录
- 动态类型映射：创建队伍、发布任务、认领任务、完成提交
- 首页作为 tab 首屏，打开即看到队伍最新动态

### 阶段七：UI 美化与细节打磨（约 2 小时）

**目标**：提升视觉体验，修复细节问题

**关键成果**：
- 暗色主题统一风格（#0F0F1A→#1A1A2E→#252540 三层卡片）
- 注册界面重做（去除手机号授权，仅需昵称）
- 所有列表页显示"由 XXX 发布/创建/上传"的操作人信息
- 交付物预览全面支持（在线预览、保存到本地、复制链接）

## 5. 总结与心得

### 数据统计（截至提交）

| 指标 | 数量 |
|------|------|
| 页面数 | 11 |
| 云函数数 | 15 |
| 代码总行数 | ~5,300 行 |
| 数据库集合 | 6 个（users/teams/tasks/members/deliverables/activities） |
| 开发用时 | 约 2 周（非全职） |

### 使用 TRAE 的感受

最大的感受是**开发效率的质变**。传统方式写一个完整的微信小程序（含云函数、数据库设计、页面交互），对个人开发者来说至少需要 4-6 周。而 TRAE 把这个周期压缩到了 2 周。

让我印象深刻的能力：
1. **代码理解能力**：TRAE 能理解已有的代码上下文，不会"前面加个变量后面忘掉"
2. **Debug 能力**：遇到的几个 bug（跨设备同步、字段名错误等），TRAE 能定位根因并给出修复方案
3. **设计建议**：缓存策略、附件数据结构设计等，TRAE 给出了比我自己想更优的方案
